## Manifesthash

`bc_data.filter_manifest.values_sha256` is **geen voorwaarde** voor deze gerichte
Typesense-PATCH. De onderzochte zoek-API leest typed documentvelden, geen
Shopify-manifest en geen manifesthash. Het veld bestaat al in het schema.
`run_index.py` controleert de bytes van een volledige vaste export; dat is een
andere hash en een ander pad. Geen hash verzonnen en geen manifest gewijzigd.

De nieuwe back-upchecksum is uitsluitend SHA-256 van canoniek geserialiseerde
back-upinhoud en wordt expliciet als zodanig gelabeld. De bestaande
schema-metadata/payloadhash blijft een verwijzing naar de oorspronkelijke export,
geen nieuw bewijs dat de levende index na een documentcorrectie bytegelijk is
aan die export. Bij een latere volledige indexopbouw moet het bevestigde aantal
kraangaten in de brongeneratie worden meegenomen; anders kan een upsert de
correctie verwijderen. Dat vervolg is vastgelegd, niet uitgevoerd.

## Script en beveiliging

[Correctiescript op actieve branch](https://github.com/jlamping1997/badkamercity/blob/fix/product-cards-2026-10-14/scripts/correct-wiesbaden-243710-filter.py)
en [offline tests](https://github.com/jlamping1997/badkamercity/blob/fix/product-cards-2026-10-14/scripts/test-wiesbaden-243710-filter.py).

De enige normale schrijfaanvraag is:

```http
PATCH /collections/bc_verified_full_20261013_874e415c15/documents/10657256210698?dirty_values=reject
Content-Type: application/json

{"f_aantal_kraangaten":1}
```

Deze gedeeltelijke update is een ondersteunde
[Typesense-documentoperatie](https://typesense.org/docs/27.0/api/documents.html#update-a-single-document).
Bij herstel wordt alleen hetzelfde veld teruggezet. Was het veld oorspronkelijk
afwezig, dan verwijdert een PATCH met `null` het optionele veld, volgens het
[Typesense-contract](https://typesense.org/docs/27.1/api/collections.html#update-or-alter-a-collection).
Geen documentverwijdering of volledige upsert nodig.

Het script:

1. Leest de sleutel intern uit de bestaande kandidaatcontainer. Geen sleutel in
   argumenten, uitvoer, back-up of Git; geen ruwe `docker inspect`-uitvoer.
2. Controleert containerindex, direct serverschema, document-ID/SKU, alle vier
   collectie-IDs/handles, beide API-healthchecks en beide bereikprofielen.
3. Controleert de huidige zoekuitkomsten op de lokale API én openbare route.
4. Schrijft vóór PATCH een volledige oorspronkelijke documentback-up met schema,
   nulmeting en checksum, via exclusieve creatie en `fsync`.
   Map `0700`, bestand `0600`, root-owned. Bestaande back-up wordt niet overschreven.
5. Vergelijkt het document nogmaals vóór schrijven en volledig na schrijven.
   Alle niet-doelvelden moeten exact gelijk blijven, inclusief prijs, URL,
   publicatie, collecties, geïndexeerde titel en overige brondata.
6. Controleert beide API's: baseline vindt deze SKU, 1..1 vindt exact dit document,
   2..2 vindt nul. Een afzonderlijke `verify` herhaalt de controles.
7. Probeert na een mislukte toepassing/controle gericht herstel, alleen bij een
   exact verwacht document. Bij concurrerende wijzigingen stopt het zonder
   die andere gegevens terug te schrijven. HTTP 401/403 wordt herkenbaar gemeld;
   ruwe serverinhoud en credentials blijven verborgen.

De lokale proceslock voorkomt twee gelijktijdige uitvoeringen van dit script.
Typesense biedt hier geen atomaire compare-and-swap: een andere serverwriter
wordt niet vergrendeld. De minimale PATCH en volledige vergelijking beperken
het risico; bij een gedetecteerd conflict volgt geen blinde herstelwrite.

## Exact uitvoeren vanuit PowerShell

Open **PowerShell op dezelfde Windows-pc**. De lokale projectbranch bevat het
voorbereide script. Voer dit blok uit; iedere fout stopt het blok:

```powershell
$script = 'C:\Users\LauraHarrySuiker\Projects\badkamercity\scripts\correct-wiesbaden-243710-filter.py'
$server = 'ubuntu@57.129.175.195'
$remoteScript = '/home/ubuntu/bc243710-filterfix-20261020.py'

scp $script "${server}:$remoteScript"
if ($LASTEXITCODE -ne 0) { throw 'Overzetten mislukt; niet verder uitvoeren.' }

ssh -t $server "sudo python3 $remoteScript inspect"
if ($LASTEXITCODE -ne 0) { throw 'Voorcontrole geblokkeerd; niet toepassen.' }

ssh -t $server "sudo python3 $remoteScript apply"
if ($LASTEXITCODE -ne 0) { throw 'Toepassing/controle geblokkeerd; lees de geschoonde melding.' }

ssh -t $server "sudo python3 $remoteScript verify"
if ($LASTEXITCODE -ne 0) { throw 'Eindcontrole niet geslaagd.' }
```

Voer wachtwoorden uitsluitend in de normale SSH-/sudo-prompt in. Het script
vraagt geen wachtwoord en heeft geen extra Pythonpackages nodig.
De back-up staat vast op:
`/var/backups/badkamercity-243710/filterfix-20261020.json`.

`apply` mag alleen `APPLIED_VERIFIED` of `ALREADY_CORRECT_VERIFIED` melden
wanneer de volledige controles slagen. `verify` moet `VERIFIED` tonen.
De JSON bevat per `local` en `public` de baseline-, `1`- en `2`-uitkomst.
Deel deze geschoonde uitvoer voor de bewijsregistratie; geen volledige back-up
of containerconfiguratie nodig.

**Alleen bij gewenst terugzetten**, niet standaard na een geslaagde toepassing:

```powershell
ssh -t ubuntu@57.129.175.195 "sudo python3 /home/ubuntu/bc243710-filterfix-20261020.py rollback --backup /var/backups/badkamercity-243710/filterfix-20261020.json"
```

Verwachte herstelstatus: `ROLLED_BACK_VERIFIED`. Bij `BLOCKED` blijft de
back-up intact; deel alleen `reason`/status. Een herstelde oude ontbrekende
kraangatenwaarde maakt het product vanzelf weer onvindbaar bij 1..1.
